# Решения и допущения

## Удаление истории

Используем физическое удаление записей с каскадом (`ON DELETE CASCADE`). Историю нельзя напрямую создать, изменить или удалить через API от имени обычного пользователя: записи добавляют только RPC создания задачи и смены статуса. При удалении задачи её история удаляется; при удалении объекта удаляются его задачи и их история. Это принятое допущение для данного тестового задания.

## Роли и назначение задач

Назначать задачи можно только пользователям с ролью `worker`. Проверка выполняется в базе данных в RPC `create_task` и `update_task_details`, включая запросы в обход интерфейса. Создание, редактирование и удаление задач разрешены постановщикам. RPC изменения задач недоступны ролям `PUBLIC` и `anon`; вызовы разрешены `authenticated`, а права конкретного пользователя проверяются внутри функций.

## Регистрация

Открытая регистрация отключена в настройках Supabase Auth. При проверке 4 ноября 2026 года endpoint `/auth/v1/settings` вернул `disable_signup: true`. Тестовые учётные записи создаются вручную в Supabase. Для нового окружения эту настройку нужно выставить отдельно: SQL-миграции не управляют настройками Auth.
